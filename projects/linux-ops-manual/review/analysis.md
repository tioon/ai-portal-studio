# Linux Ops Manual 정밀 분석

분석일: 2026-10-12 · 대상: 공개 페이지 및 `projects/linux-ops-manual/` 소스

## 1. 결론

**이 문서만으로 리눅스를 모두 안다고 할 수는 없습니다.** 현재 성격은 “Rocky Linux / Ubuntu 서버 운영용 명령어 레퍼런스”입니다. 일상 점검의 출발점으로는 유용하지만, 기초부터 배우는 교재나 장애 복구 절차서, 배포판별로 검증된 운영 매뉴얼은 아닙니다.

명령어 이름을 아는 것과 운영 능력은 다릅니다. 명령의 출력 해석, 실행 조건, 변경 영향, 실패 후 복구까지 알아야 실제 운영에 사용할 수 있습니다. Linux에는 커널뿐 아니라 셸, GNU 유틸리티, 배포판 도구, 추가 패키지가 함께 존재하므로 고정된 “모든 명령어 목록”도 없습니다.

이번 작업은 기존 141개 항목의 UI 재설계와 확인된 검색·표시 오류 수정입니다. 누락 명령어를 모두 추가하거나 Linux 전체 교육 과정을 새로 집필한 작업은 아닙니다.

## 2. 조사 방식과 숫자의 의미

- 공개 `app.js`를 다운로드하여 로컬 소스와 SHA-1을 비교: 둘 다 `a2c098b56663dc39def3298ff8f0524f2b3cedba`로 일치했습니다(수정 전).
- 원본 데이터 배열, 분야 매핑, 배포판별 표시 로직, 검색·렌더링·복사 경로를 조사했습니다.
- 141개 데이터 항목, 29개 분야, 282개 배포판 variant, 중복 ID 0개입니다.
- 수정 전 양쪽 배포판을 합하면 옵션 레코드 1,193개, 예시 레코드 684개입니다. **중복을 포함한 레코드 수이며 고유 명령어 수가 아닙니다.**
- `ps / top / pgrep / kill`처럼 여러 도구가 한 항목에 들어갑니다. 반대로 `journalctl`, `journalctl advanced`, 로그 묶음은 내용이 겹칩니다. 따라서 “141개 명령어” 또는 임의의 “Linux 커버리지 90%”로 표현하면 부정확합니다.
- 누락 여부는 원본 본문의 식별자 검색과 해당 분야 데이터 검토로 구분했습니다. 단순 문자열 출현을 사용법 설명으로 계산하지 않았습니다.
- 브라우저 동작은 실제 Chromium으로 검증했습니다. **실제 Rocky/Ubuntu 서버에서 684개 예시를 실행한 것은 아닙니다.**

## 4. 실제로 빠진 명령어

다음은 **원본 `app.js`에서 해당 명령 식별자가 확인되지 않은 사례**입니다. Linux 기본 설치에 모두 포함되는 것은 아니며 추가 패키지가 필요한 도구도 있습니다. 전체 누락 목록을 의미하지 않습니다.

| 영역 | 누락 사례 | 학습상 필요한 이유 |
| --- | --- | --- |
| 셸 기본/스크립트 | `export`, `read`, `trap`, `getopts`, `umask`, `ulimit` | 환경 변수, 입력, 종료 처리, 옵션 파싱, 기본 권한, 자원 제한 |
| 기본 유틸리티 | `wc`, `basename`, `realpath`, `timeout` | 데이터 집계, 경로 처리, 실행 시간 제한 |
| 동시 실행/자동화 | `flock` | cron 중복 실행 및 잠금 |
| 구조화 데이터 | `jq`, `yq` | JSON/YAML 처리 |
| 네트워크 설정 | `resolvectl` | systemd-resolved DNS 상태·문제 진단 |
| 프로세스 격리 | `lsns`, `nsenter`, `unshare` | 컨테이너와 namespace 이해 |
| CPU/NUMA | `taskset`, `numactl` | CPU affinity와 NUMA 배치 |
| 장치 상태/암호화 | `smartctl`, `cryptsetup` | 디스크 건강 확인, LUKS 암호화 |
| 커널 모듈 | `lsmod`, `modprobe` | 로드된 모듈과 드라이버 관리 |
| 부팅/복구 | `dracut`, `update-initramfs`, `grub-mkconfig` | initramfs/부트로더 이해와 복구(배포판별 도구명·절차 확인 필요) |
| 고급 관측 | `bpftrace` | 커널·사용자 공간 이벤트 추적 |

### 이름이 보이는 것과 학습 가능한 것은 다릅니다

- `netplan`: 차이 설명에 언급되지만 YAML 구조, renderer, 적용·검증·되돌리기 절차가 없습니다.
- `nvme`: `/dev/nvme0n1` 같은 **장치명**은 있지만 `nvme-cli`의 `nvme smart-log` 사용법이 있는 것은 아닙니다.
- `perf`, `mdadm`, `btrfs`, `nft`: 이미 묶음 항목에 있습니다. “누락”으로 세면 안 됩니다. 다만 상세 운영 절차는 부족합니다.
- `man`, `apropos`, `help`, `cp`, `mv`, `rm`, `mkdir`: 이미 포함되어 있습니다. 기초 명령이 전혀 없는 사이트라는 평가는 틀립니다.

## 5. 명령어보다 더 중요한 학습 공백

1. **셸의 실행 규칙**: quoting, glob, 변수 확장, 표준 입출력, 리다이렉션 순서, 파이프, exit code, `&&`/`||`, 반복문과 함수. 파이프 예시가 존재하는 것과 이 규칙을 설명하는 것은 다릅니다. [GNU Bash 기본 기능](https://www.gnu.org/software/bash/manual/html_node/Basic-Shell-Features.html)
2. **파일·프로세스 모델**: inode, hard/symbolic link, file descriptor, `/proc`, `/sys`, 시그널, 좀비, open-but-deleted 파일.
3. **부팅과 복구**: firmware→bootloader→kernel→initramfs→systemd, emergency mode, 잘못된 fstab, 부팅 불가 복구.
4. **지속되는 네트워크 구성**: DNS 해석 흐름, renderer 선택, 정적 IP, bond/bridge/VLAN, 원격 변경 롤백. Netplan은 `networkd`와 `NetworkManager` renderer를 구분합니다. [Netplan 공식 문서](https://netplan.readthedocs.io/en/stable/netplan-yaml/)
5. **운영 절차**: 백업→변경→검증→롤백, 복원 실습, 모니터링 기준선, 장애 후 회고. 명령어 복사 기능으로 대체할 수 없습니다.
6. **권한과 격리**: umask, capabilities, PAM/NSS, SELinux 문맥과 정책, cgroup/namespace.
7. **실습과 판단 기준**: 정상/비정상 출력, 서비스 중단 여부, 테스트 환경, 성공 조건, 실패 조건이 일관되게 없습니다.

Linux 매뉴얼 자체도 사용자 명령(1), 시스템 호출(2), 라이브러리(3), 파일 형식(5), 개념(7), 관리자 명령(8) 등으로 나뉩니다. 명령어 레퍼런스 하나가 이 전체를 대신할 수는 없습니다. [Linux man-pages](https://man7.org/linux/man-pages/)

## 6. 발견한 기능·내용 문제와 처리

| 문제 | 수정 전 근거 | 이번 처리 |
| --- | --- | --- |
| 상황별 버튼 3개가 0건 반환 | `terms.every`로 `df du find journalctl` 등의 모든 단어가 한 항목에 있어야 통과. 디스크 0, 서비스 0, 로그 0, 포트 1 | 일반 검색의 AND 규칙은 유지, 바로가기는 검토된 ID 묶음으로 분리. 기존 분야/검색 필터도 해제 |
| 타 배포판 명령이 기본 코드로 표시 | `dnf-history` 등 6개 항목에 표시 override 없음. Ubuntu로 바꿔도 기본 `dnf` 문자열 사용 | 배포판별 기본 코드 및 제목 대응 추가 |
| 여러 배포판 명령 연결 | `yum install pkg && apt-get install -y pkg && rpm -q nginx` | 기본 예시를 Rocky `rpm -q nginx`, Ubuntu `dpkg -s nginx`로 분리 |
| 상태 조회와 변경 작업 연결 | `systemctl status nginx && systemctl restart nginx` | 기본 코드는 상태 조회만. 변경 예시는 상세 영역에 유지 |
| 서로 다른 파일시스템 도구 연결 | `tune2fs -l /dev/sda1 && xfs_info /dev/sda1 && fstrim -av` | 기본 코드는 `lsblk -f`로 교체. 개별 유지보수 예시는 별도 검토 필요 |
| 표시용 코드가 HTML로 해석됨 | 예시를 `innerHTML`에 삽입. `ltrace -p <pid>`의 `<pid>`가 태그가 됨 | 코드·옵션·설명에 `textContent` 사용 |
| 복사 실패가 처리되지 않음 | clipboard Promise에 예외 처리 없음 | 실패 시 명령 선택 및 안내, 성공·실패 상태 알림 |
| 일반 명령도 배포판 전용이라고 표시 | `Rocky Linux only`, `Ubuntu only`, “전용 보기” | 기준 배포판 선택으로 정리, 중복 배지 제거 |
| 존재하지 않는 명령처럼 보이는 설명 | 옵션에 `apt history` 표시 | APT 이력 로그 파일 경로로 수정 |
| Ubuntu 네트워크 관리자 일반화 | `nmcli`가 일반적인 실제 상태 확인 경로라는 설명 | NetworkManager가 관리하는 연결에 한정, networkd 구분 명시 |
| 과장된 제품 표현 | “10초 안에”, 정적 문서의 `Live` 배지 | 검증 불가능한 홍보 문구 제거 |

### 아직 남아 있는 콘텐츠 과제

- 배포판의 **버전**, 설치 패키지, 최소 도구 버전, 필요한 권한, 검증 일자가 항목별 메타데이터로 없습니다. “Rocky/Ubuntu 지원”이 모든 버전에서 검증되었다는 뜻은 아닙니다.
- 대표 코드 일부만 정리했습니다. 기존 상세 예시 전부가 정밀 교정된 것은 아닙니다. `pkg`, `host`, 장치명, 인터페이스 이름 등 환경별 치환이 필요합니다.
- `dnf versionlock` 등 플러그인 설치가 필요한 명령의 전제 조건은 별도 보완이 필요합니다.
- `mkfs`, `pvcreate`, `fsck`, `xfs_repair`, `blkdiscard` 등의 위험/변경 명령은 여전히 포함됩니다. 개별 경고는 있지만 사전 확인·백업·성공 검증·복구 절차가 충분하지 않습니다.
- `fsck`는 LVM/스왑 분야에 배치되어 있으나 일반 파일시스템 복구 도구입니다. `semanage` 등도 분야가 겹칩니다. 후속 편집에서 재분류를 권합니다.
- `displayOverrides` 안에 동일 키를 반복 선언한 부분이 있어 나중 값이 앞의 값을 덮어씁니다. 데이터 구조 정규화가 필요합니다.
- 검색은 문자열 포함 기반입니다. 자연어 검색 엔진이 아니며, 동의어·형태소·오타 교정·관련도 정렬을 제공하지 않습니다.

## 7. UI 재설계

**방향: 홍보용 랜딩 페이지 → 운영자가 반복해서 사용하는 기술 문서.**

- 흰 배경, 회색 구분선, 절제된 파란 강조색; 네온·그라데이션·유리 효과·큰 그림자 제거.
- 좌측 분야 목차 + 본문 단일 열; 분야별 개수와 현재 선택 상태 표시.
- 상단 검색과 배포판 선택을 한 작업 영역으로 묶고 빠른 점검은 4개만 유지.
- 명령어, 설명, 코드, 상세 정보를 일관된 순서로 정렬. 과도한 태그·카드 중첩 제거.
- 코드에 시스템 monospace 폰트 사용; 외부 Google Fonts 의존성 제거.
- 모바일 목차는 접기/펼치기, 긴 명령어는 줄바꿈, 상세는 한 열로 변경.
- 검색 `/` 단축키, 본문 바로가기, 키보드 포커스, 버튼 선택 상태와 복사 상태 알림 추가.
- 단순 예쁜 화면보다 탐색의 예측 가능성, 읽기 순서, 작업 집중도를 우선했습니다.

## 9. 다음 콘텐츠 작업의 우선순위

1. **정확성부터**: 항목을 명령 단위로 정규화하고 중복 제거. 배포판·버전·패키지·권한·출처·검증일 추가.
2. **기초 학습 경로**: 셸→파일/권한→프로세스→서비스→네트워크→스토리지 순서의 짧은 실습.
3. **운영 절차서**: 디스크 부족, 서비스 기동 실패, SSH 접속 실패, DNS 오류, 부팅 실패에 대해 관측→판단→조치→검증→롤백 작성.
4. **고급 영역**: 성능·NUMA·cgroup/namespace·커널 모듈·디스크 건강·복구 실습 추가.

목표는 “모든 명령어를 넣었다”가 아니라, **정해진 운영 과업을 올바르게 완료할 수 있는 문서**여야 합니다.
